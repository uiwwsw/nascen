# Experiment 011 · 원리 설명을 배워 새로운 조건에 적용하기

Nascen의 질문은 **문장으로 전달된 조건과 예외를 학습하면, 관찰하지 않은 조합을 더 적은 경험으로 판단할 수 있는가**입니다. 하나의 시험용 표시등이 켜지는 조건을 예측하는 모의 환경에서 이 질문을 확인했습니다.

## 문장 표현 기반

Meta LCM은 SONAR의 문장 임베딩 공간에서 다음 문장을 예측합니다. 공식 저장소는 MIT 라이선스의 학습·평가 코드와 체크포인트를 등록하는 재현 절차를 제공합니다. 저장소에서 바로 사용할 수 있는 공식 LCM 사전학습 체크포인트는 확인하지 못했습니다. 별도로 공개된 SONAR 모델 가중치에는 CC BY-NC 4.0 조건이 적용됩니다. [Meta LCM 논문](https://arxiv.org/abs/2412.08821) · [공식 코드와 재현 절차](https://github.com/facebookresearch/large_concept_model) · [SONAR 모델 라이선스](https://github.com/facebookresearch/SONAR/blob/main/NC_MODEL_LICENSE.md)

이번 CPU 실험은 설치된 고정 다국어 E5를 모든 비교군에서 동일하게 사용합니다. 코드는 기존 문장 인코더 인터페이스를 재사용합니다. 문장 모델 간 성능 비교는 이번 평가에 포함하지 않았습니다. [E5 모델과 가중치](https://huggingface.co/intfloat/multilingual-e5-small)

## 무엇을 학습하는가

버튼을 누르기 전 장치에는 네 가지 관측 사실이 있습니다. 원리 수업은 그중 두 조건이 모두 필요한지 또는 하나만 필요한지, 그리고 어떤 예외가 결과를 뒤집는지를 설명합니다. 다섯 필드는 두 조건, 연결 방식, 우선 적용될 예외와 그 반례입니다.

1. 공통 모델은 조건 문장과 관측 문장이 대응하는지, 조건이 성립하는지, 그 결과 표시등이 켜지는지를 학습합니다. 두 조건과 예외를 어떤 방식으로 종합할지는 전이 신경망이 학습합니다.
2. 새 수업의 문장 벡터를 학습한 변환층으로 보내 **160개 값의 원리 가중치**를 만듭니다. 새로 관찰한 결과가 있으면 공통 모델을 고정하고 원리 가중치만 갱신합니다.
3. 추론은 체크포인트와 네 관측 문장을 입력받습니다. 수업 원문, 원리 번호, 정답 생성기와 교사 서버는 추론에 필요하지 않습니다. 추가 관찰로 가중치를 이어서 갱신하거나, 수정 수업으로 새 가중치를 쓸 수 있습니다.

## 비교 설계

- 사전 학습은 원리 128개에서 만든 4,096개 관찰·표현을 사용합니다. 여기에는 절이 어느 관측에 대응하는지와 그 조건의 성립 정답도 들어 있습니다.
- 사전 학습에서 **두 조건과 예외가 묶이는 방식 네 가지**를 통째로 뺐습니다. 그 안에서 연결 방식과 조건의 긍정·부정이 다른 원리 8개를 시험했습니다. 원리마다 경험 0·2·4·8개와 별도의 평가 조합 8개를 사용했습니다. 모든 모델은 동일한 공통 가중치, 경험, 시드와 갱신 방식으로 비교했습니다.
- **경험만**, **경험과 관련 수업**, **경험과 무관한 수업**을 비교했습니다. 무관한 수업은 같은 연결 방식인 다른 원리에서 가져왔습니다. 경험 순서는 원리의 정답을 참조하지 않고 결정했습니다. 켜짐과 꺼짐의 재현율을 같은 비중으로 평균한 균형 정확도를 주 지표로 사용했습니다. 경험 예산을 비교할 기준은 균형 정확도 80%입니다.
- Qwen에는 알려진 규칙의 문장만 주고 한국어 수업으로 정제하게 했습니다. 실제 경험이나 평가 문항은 전달하지 않았습니다. 첫 수집에서 8개 중 하나가 ‘코드 검증’을 ‘전원’으로 잘못 바꿨습니다. 수정 전후 응답을 남기고 최종 수업 8개를 조건·예외 명세와 대조했습니다. 수정까지 총 9회 요청, 2,976토큰, 약 22.2초가 들었습니다. [교사 응답](experiment-011-lessons.json) · [검토 기록](experiment-011-review.json)

## 결과

균형 정확도는 8개 원리와 세 시드의 평균입니다.

| 새 원리에서 관찰한 경험 | 경험만 | 관련 원리 + 경험 | 무관한 원리 + 경험 |
| ---: | ---: | ---: | ---: |
| 0 | 50.0% | 100.0% | 48.6% |
| 2 | 61.7% | 83.9% | 45.6% |
| 4 | 63.2% | 92.9% | 51.6% |
| 8 | 62.4% | 100.0% | 51.8% |

관련 수업을 쓰면 새 규칙의 경험을 추가하기 전에도, 경험만 사용하는 쪽이 틀린 **48개 판단이 정답으로 바뀌고 맞던 판단의 퇴행은 0개**였습니다. 원리 8개 × 시드 3개 × 평가 조합 8개에 대한 결과입니다. 목표 균형 정확도 80%에는 관련 원리 조건이 첫 예산인 0개에서 도달했습니다. 경험만 사용한 조건과 무관한 원리 조건은 시험한 최대 예산 8개까지 도달하지 못했습니다. 이 경험 수에는 공통 사전 학습량과 교사 수업 비용이 포함되지 않습니다.

경험을 두 개 추가하자 관련 수업 조건의 균형 정확도가 100.0%에서 83.9%로 떨어졌습니다. 소수의 관찰로 원리 가중치를 갱신하는 방식에 안정성 문제가 남아 있습니다. 경험을 여덟 개 모두 준 경우에는 관련된 세 조건의 조합을 이미 전부 관찰하므로, 이때의 평가에는 무관한 네 번째 사실만 달라진 사례가 포함됩니다. 원리 학습 효과는 새 경험으로 관련 조건을 덜 본 0·2·4개 결과와 함께 해석해야 합니다. [원본 결과와 시드별 예측](experiment-011.json)

이 시험의 대상은 사람이 명세하고 교사가 정제한 원리를 단일 모의 환경에서 새 조건 조합에 적용하는 능력입니다. 평가 관측은 사전 학습과 같은 제한된 어휘와 표현군에서 가져왔습니다. 관찰만으로 새 원리를 발견하거나, 다른 분야로 옮길 수 있는지는 각각 별도 검증이 필요합니다.

## 실행

설치된 E5 스냅샷과 저장된 교사 수업으로 전체 비교를 재현할 수 있습니다.

```sh
python -m nascen.theory_language.principle_study benchmark \
  --output .nascen/experiment-011.json \
  --checkpoint .nascen/theory-language/principle-study-011.pt
```

공통 모델을 직접 만들고 수업을 한 건 학습시키는 예입니다. `lesson.json`에는 `first`, `second`, `logic`, `exception`, `counterexample`의 문장을 넣습니다. 예시는 저장된 수업의 첫 원리를 꺼내 사용합니다.

```sh
python -m nascen.theory_language.principle_study train --output .nascen/theory-language/principle-base-011.pt
python -c 'import json; d=json.load(open("docs/experiment-011-lessons.json")); json.dump(d["lessons"]["lesson-01"],open(".nascen/theory-language/lamp-lesson.json","w"),ensure_ascii=False)'
python -m nascen.theory_language.principle_study study \
  --base .nascen/theory-language/principle-base-011.pt \
  --lesson .nascen/theory-language/lamp-lesson.json \
  --output .nascen/theory-language/lamp-student-011.pt
python -m nascen.theory_language.principle_study predict \
  --checkpoint .nascen/theory-language/lamp-student-011.pt \
  --facts '전원 접점이 연결되어 있다.' '보호 덮개가 닫혀 있다.' \
          '확인 코드 검사를 통과하지 않았다.' '정비 모드가 켜져 있다.'
```

저장하고 불러온 기본 시드 모델은 이 예에서 ‘켜진다’를 출력했습니다. 코드에 관한 문장만 ‘확인 코드 검사를 통과했다’로 바꾸면 ‘꺼진 상태로 남는다’를 출력했습니다.

`study --observations`는 `{"facts":[문장 네 개],"lit":true}` 형태의 JSON 배열을 받습니다. 현재 명령은 새 관찰을 이미 맞히면 가중치를 유지합니다. 예측과 관찰이 충돌하면 이전에 저장한 검증 사례나 같은 형식의 `--verify` 파일에 갱신용 관찰과 별개의 사례가 있어야 수정할 수 있습니다. 새 관찰과 검증 사례를 모두 맞혀야 제안을 저장합니다. 위 실험 표는 당시 방식대로 재현할 수 있습니다. [변경 리포트](principle-update.md)
