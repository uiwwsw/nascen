## Experiment 001 · 규칙 발견

에이전트는 밀기 전후에 직접 관찰한 위치를 사건으로 기록합니다. 주변 타일과 밀기 방향을 조합해 조건부 규칙을 만들고, 예측 오차와 반례, 조건의 개수를 함께 고려해 규칙을 고릅니다. 능동 탐색은 경쟁 규칙이 서로 다른 결과를 예상하는 밀기를 우선합니다.

5개 시드에서 조건당 24번 밀었습니다. 학습 중 등장하지 않은 영역과 색·형태 조합으로 만든 61개 상황에서, 밀기 후 물체의 위치를 평가했습니다.

| 모델 · 실험 선택 | 최종 위치 정확도 | 기준에 도달한 시드 | 도달까지 평균 실험 | 평균 CPU 시간 |
| --- | ---: | ---: | ---: | ---: |
| 조건부 규칙 · 능동 | 100% | 5/5 | 3회 | 26.9 ms |
| 조건부 규칙 · 무작위 | 100% | 5/5 | 3회 | 11.5 ms |
| 소형 신경망 · 무작위 | 63.3% | 0/5 | — | 7.7 ms |

기준은 3회 연속 위치 정확도 95% 이상을 처음 달성한 시점입니다. 두 규칙 모델은 모든 시드에서 ‘밀 방향의 칸이 비면 한 칸 이동한다’는 조건과 그 외의 정지 결과를 찾아냈습니다. 이 작은 환경에서는 무작위 선택도 같은 횟수로 규칙을 찾았습니다. CPU 시간은 한 기기에서 실험 선택·실행과 학습을 측정한 값이며, 공통 실험 준비와 별도 평가 비용은 제외했습니다. 규칙 탐색은 시야의 범주형 특징과 두 조건까지의 문법을 사용합니다.

```sh
python -m nascen.evaluation --measure-time
```

실험별 밀기 전후 상태, 반례 수, 발견한 규칙, 예측 정확도와 비용을 확인할 수 있습니다. [Experiment 001 원본](experiment-001.json)

## Experiment 002 · 교사 없이 답하기

로컬 Qwen3-4B에 가상의 물건 사용 규칙을 알려주고 수업 100개를 받았습니다. 각 수업은 결정, 구조화된 근거 코드, 한 문장 설명을 담습니다. 교사 응답 중 89개는 결정과 근거 코드가 내부적으로 일치했고, 33개는 두 항목 모두 독립 채점 규칙과 일치했습니다. 확인된 33개만 쓰는 비교군에는 교사 응답에서 통과한 사례를 그대로 사용했습니다. [교사 수업 원본](experiment-002-lessons.json) · [Qwen 모델 카드](https://huggingface.co/Qwen/Qwen3-4B-GGUF)

시험은 교사 서버를 종료한 뒤 저장된 학생 가중치로 실행했습니다. 수업에 등장하지 않은 장소·동의·긴급성·대안·사용 범위 조합 50개를 두 문장 형식으로 제시했습니다. 서로 다른 초기화 시드 3개의 평균입니다.

| 학생 | 사용한 수업 | 결정 정확도 | 결정·근거 동시 정답 | 정답이 바뀌는 문항 쌍 |
| --- | ---: | ---: | ---: | ---: |
| 무작위 초기화 · 결정 | 89 | 58.7% | — | 0.0% |
| 무작위 초기화 · 결정과 근거 | 89 | 61.3% | 40.0% | 0.0% |
| 무작위 초기화 · 검증된 결정과 근거 | 33 | **80.0%** | **78.0%** | **4.2%** |
| 사전학습 MiniLM · 결정과 근거 | 89 | 55.3% | 36.7% | 0.0% |

문항 쌍 8개는 긴급 여부만 바꾸면 정답이 달라집니다. 가장 좋은 학생도 3개 시드를 합친 24쌍 중 1쌍에서만 두 결정을 모두 맞혔습니다. 이 학생의 결정과 근거 코드가 서로 일치한 비율은 92.7%였습니다. 문장 두 형식의 일치는 정해진 표현을 구조화하는 공통 파서의 결과입니다. 이 실험에서 학생이 학습하는 근거는 코드이며, 교사가 쓴 설명 문장은 검토용으로 보존합니다. MiniLM 비교군은 영어 표현을 인코딩하는 고정 사전학습 모델 위의 분류기만 학습합니다. [시험 원본과 세부 채점](experiment-002.json) · [MiniLM 모델 카드](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)

```sh
python -m nascen.distillation train --lessons docs/experiment-002-lessons.json --output .nascen/student.json
python -m nascen.distillation exam --student .nascen/student.json
```

MiniLM 비교군까지 실행하려면 해당 모델의 로컬 스냅샷을 준비하고 두 명령에 같은 `--minilm PATH`를 추가합니다. 재현에 사용한 스냅샷은 `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`입니다. 고정 인코더에 필요한 패키지는 `python -m pip install -r requirements-teacher.txt`로 설치합니다.

새 수업을 수집할 때는 Qwen3-4B GGUF를 llama.cpp의 `127.0.0.1:8766`에서 실행한 뒤 다음 명령을 사용합니다. 기존 실험 결과를 재현할 때에는 저장된 수업을 사용합니다.

```sh
python -m nascen.teacher --teacher 'Qwen/Qwen3-4B-GGUF Q4_K_M' --output .nascen/new-lessons.json
```

## Experiment 003 · 문장과 조건의 일반화

Experiment 002의 수업 파일과 무작위 초기화 학생을 재사용했습니다. 수업 중 결정과 근거가 모의 규칙에 모두 일치한 사례로 학습했고, 교사 모델 호출 없이 시드 11·22·42로 평가했습니다. 입력을 구조화하는 단계와 구조화된 사실로 판단하는 단계를 따로 시험했습니다.

### 새 문장 표현

Experiment 002의 미학습 사례 50개에 같은 사실을 담았습니다. 기존 문형, 긴급성 문장만 바꾼 문형, 문단 전체를 다시 쓴 문형을 같은 학생에게 제시했습니다. 구조화된 사실을 직접 주는 조건도 함께 측정했습니다.

| 입력 | 파서가 처리한 문항 | 결정 정확도 |
| --- | ---: | ---: |
| 기존에 지원하는 문형 | 50/50 | 80.0% |
| 긴급성 문장 한 줄만 새 표현 | 0/50 | 0.0% |
| 새 서술형 문단 | 0/50 | 0.0% |
| 구조화된 사실 직접 제공 | 파서 생략 | 80.0% |

파서가 거부한 문항은 전체 정확도 계산에서 오답으로 집계했습니다. 두 새 문형의 0%는 학생이 결정을 내리기 전에 발생한 입력 처리 실패입니다.

### 학습에 없던 조건 조합

소유자에게 제때 답을 받을 수 없는 사례에서, 유효한 대안 유무와 사용 범위의 조합을 하나씩 뺐습니다. 각 조합에 대해 여섯 장소와 두 긴급성 상태를 **전부** 학습에서 제외하고, 학생을 다시 학습시켜 구조화된 12개 사례를 시험했습니다. 쌍의 두 사례는 긴급성만 다르며, 두 결정을 모두 맞혀야 쌍 정답으로 집계합니다.

| 유효한 대안 | 필요 범위로 제한 | 사용한 수업 | 예시가 빠진 근거 | 결정 정확도 | 쌍 정확도 |
| --- | --- | ---: | --- | ---: | ---: |
| 없음 | 아니요 | 30 | 사용 범위 초과 | 11.1% | 0.0% |
| 없음 | 예 | 32 | 긴급 예외 | 0.0% | 0.0% |
| 있음 | 아니요 | 32 | 유효한 대안 | 55.6% | 11.1% |
| 있음 | 예 | 33 | — | 11.1% | 0.0% |

결정 정확도는 전체 평균 19.4%였고, 세 시드를 합친 72쌍 중 2쌍을 맞혔습니다. 두 근거가 모두 학습에 남아 있던 조건에서도 쌍 정확도는 0%였습니다. 나머지 세 조건에서는 정답 근거 중 하나의 학습 예시가 빠져, 새 근거 범주에 대한 판단도 함께 시험했습니다.

```sh
python -m nascen.generalization --lessons docs/experiment-002-lessons.json
```

문항 원문과 정답, 각 조건에서 제외되거나 실제 사용된 수업 ID, 시드별 응답을 확인할 수 있습니다. [Experiment 003 원본](experiment-003.json)

## v0.3 · 선택 학습

검증기는 가중치를 갱신하기 전에 관찰, 멘토 답변과 직접 밀어 본 결과를 평가합니다. 같은 시야 특징이나 밀기 조건을 뒷받침하는 증거를 모으고, 출처와 관찰 대상이 같은 반복 답변은 한 표로 집계합니다. 두 증거 이상이 일치하고 경쟁 가설보다 지지가 높을 때, 현재 예측의 불확실성과 기존 학습 횟수로 가치를 계산합니다. SQLite에는 관찰과 반례, 판단 근거, 가중치를 함께 저장합니다. 증거가 뒤집힌 경험은 이후 재사용 후보에서 빠집니다.

분리형 모델에 같은 관찰 1,000개를 주고 500개 지점에서 물체 분포를 바꿨습니다. 무작위와 선택 학습은 같은 답변 250개를 받아 50개 구간마다 같은 횟수로 갱신합니다. 오답 조건에서는 전체 답변 후보 중 20%를 합성 오답으로 바꿨습니다. 표의 정확도는 5개 시드의 최종 미학습 조합 평균입니다.

| 조건 | 받은 답변 | 평균 업데이트 · 정상 / 오답 | 정확도 · 정상 / 오답 | 오답으로 학습한 횟수 |
| --- | ---: | ---: | ---: | ---: |
| 전체 순차 학습 | 1,000 | 1,000 / 1,000 | 0.5% / 1.5% | 200.0 |
| 무작위 선별 | 250 | 95.6 / 90.0 | 45.2% / 33.2% | 17.8 |
| 검증 후 선별 | 250 | 95.6 / 90.0 | **50.4% / 39.8%** | **0.2** |

오답 조건에서 선택과 훈련을 합친 CPU 시간은 전체 학습 226.9 ms, 무작위 21.2 ms, 검증 후 선별 47.0 ms였습니다. 전체 학습은 새 물체 분할에서 100%에 도달했습니다. 세 조건 모두 최근 **학습 사례**를 재사용하므로, 갱신 횟수에 따라 버퍼가 보존하는 관찰 기간이 다릅니다.

```sh
python -m nascen.benchmark_v03 --measure-time
python -m nascen knowledge
python -m nascen --json knowledge
```

시드별 학습 곡선, 분포 전환 전후 정확도, 검증 결과와 비용을 확인할 수 있습니다. [v0.3 선택 학습 원본](benchmark-v0.3.json)

## v0.2 · 이동하며 배우기

에이전트는 사전학습 없이 무작위 가중치와 빈 경험 기록에서 출발합니다. 8×6 세계에서 한 칸씩 이동하며, 두 칸 이내의 물체를 관찰하거나 멘토에게 질문합니다. 물체를 밀려면 바로 옆에 있어야 합니다. 멘토 타일로 밀어 넣는 행동은 실행 전에 차단됩니다.

```mermaid
flowchart LR
    A["물체 관찰"] --> B["이름 또는 이동 결과 예측"]
    B --> C["이동 · 관찰 · 질문 · 밀기"]
    C --> D["결과와 피드백 기록"]
    D --> E["가중치 갱신"]
    E --> A
```

- **관찰.** 정책에는 주변 타일과 7×7 RGB 관찰만 전달됩니다. 분리형 모델은 동일 이미지에서 평균 RGB와 윤곽을 계산합니다. 공유 인코더는 원본 RGB에서 색·형태 분류에 쓰는 표현을 학습합니다.
- **질문.** 무작위, 예측 불확실성, 이전 질문에서 얼마나 예측이 좋아졌는지를 이용하는 학습 진전 전략이 있습니다. 질문마다 비용을 보상에서 차감하며, 답을 받은 경험에만 색과 형태 라벨을 기록합니다.
- **학습.** 라벨로 개념을, 밀기의 실제 결과로 이동 여부를 배웁니다. 별도의 보상 모델이 행동 결과와 멘토 피드백을 반영합니다. 경험, 위치, 설정, 가중치는 SQLite에 저장되며, `reset`은 새 실험을 시작합니다.

첫 MVP에서 ‘이름을 배운다’는 것은 고정된 색·형태 범주를 관찰에 연결하는 것을 뜻합니다. 벤치마크에 쓰는 관찰과 멘토 답변은 시뮬레이터가 생성하며, 에이전트의 행동도 그 안에서만 일어납니다.

## 바로 실행하기

새 데이터베이스는 v0.3 선택 학습으로 시작합니다. `python -m nascen knowledge`로 가설과 증거를 확인할 수 있으며, `reset --learning immediate`로 v0.2 방식도 실행할 수 있습니다.

Python 3.12~3.14와 CPU를 사용합니다. Linux x86-64와 macOS 14 이상 Apple Silicon에서 검증했습니다.

```sh
git clone https://github.com/uiwwsw/nascen.git
cd nascen
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

python -m nascen status
python -m nascen train --steps 50
```

새 데이터베이스에서는 에이전트가 실제로 이동하는 실험이 시작됩니다. `status`에서 에이전트의 위치와 시야에 들어온 물체의 번호 및 추측을 확인할 수 있습니다. 기존 v0.1 실험은 저장한 가중치와 기존 세계 규칙으로 이어집니다.

```sh
# 새 시드 42 실행에서 시작 위치에 보이는 물체
python -m nascen reset --seed 42 --question-budget 10
python -m nascen teach 2
python -m nascen feedback +1
python -m nascen --json status

# v0.1 기준 실험을 같은 시드에서 재현
python -m nascen reset --world legacy --seed 42 --strategy random
python -m nascen train --steps 50
```

`--db PATH`를 명령 앞에 두면 별도 SQLite 파일을 사용합니다. 기본 경로는 `.nascen/lab.sqlite3`입니다. `reset`에 `--no-replay`를 더하면 새 경험만으로 모델을 갱신합니다. 이동 실험의 기본 인코더는 분리형이며, `--encoder shared`로 원본 픽셀 모델을 선택할 수 있습니다.

```sh
python -m nascen reset --encoder shared --questions progress --question-budget 10 --question-cost 0.08
# 직접 답하려면 status에 표시된 물체 번호와 색·형태를 입력
python -m nascen teach 2 --color amber --shape triangle
```

## v0.2 비교 실험

같은 5개 시드에서 각 조건을 실행했습니다. 관찰 후보, 답변 수, 업데이트 횟수와 배치 크기를 조건별로 맞췄습니다. 비교용 관찰은 동일한 이동 경로에서 수집했습니다. 평가는 새 물체 배치와 렌더링으로 만든 160장의 미학습 조합에서 색과 형태를 모두 맞히는지를 측정합니다. 이 지표는 물체 분류를 평가합니다.

| 실험 | 같은 예산 | 결과 |

## v0.1 기준 실험

조건마다 동일한 5개 시드로 300단계씩 실행했습니다. 학습 세계에서 뺀 색·형태 조합 4개를 새 합성 이미지 32장으로 평가했고, **한 이미지의 색과 형태를 모두 맞혀야** 정답으로 집계했습니다.

| 탐색 | Replay | 응답 제한 없음 · 정확도 | 평균 응답 수 | 응답 40회 · 정확도 |

| 무작위 | 사용 | 36.2% | 53.6 | 30.6% |
